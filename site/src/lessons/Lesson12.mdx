<BigPicture>

Every robot program is full of numbers that someone will want to change: a speed limit, a rate, a gain, a frame name. Recompiling for each is slow, and different robots need different values from the same code. **Parameters** are named values that belong to a node, set when it starts (from a YAML file, a launch file or the command line) and, if the node allows it, changed while it runs. This lesson declares parameters in C++, sets them every way there is, and works out which value wins.

</BigPicture>

## Declaring parameters

The example is a blinking light: a node that publishes on and off on `/light`, at a rate, with a label for its log. Three parameters:

<Listing {...code.blinker} lines={[lineOf(code.blinker.code, 'class Blinker'), lineOf(code.blinker.code, "verbose_ = declare_parameter")]} highlight={at(code.blinker, 'rate_info.description', 'rate_info.floating_point_range[0].from_value', 'rate_ = declare_parameter("rate", 2.0, rate_info);', 'label_ = declare_parameter("label", "light");')} />

`declare_parameter(name, default)` creates the parameter, gives it its type (a double, from `2.0`) and returns its value: the default, or whatever overrides it at start. A **descriptor** adds a description and a range, both of which ROS then enforces and reports.

## Reacting to a change

A node that read its parameters once at start would not notice `ros2 param set`. Two callbacks handle changes: one **before** the change, which can refuse it, and one **after**, which acts on it.

<Listing {...code.blinker} lines={[lineOf(code.blinker.code, '// Before a change is made'), lineOf(code.blinker.code, 'publisher_ = create_publisher')]} highlight={at(code.blinker, 'check_ = add_on_set_parameters_callback(', 'result.successful = false;', 'apply_ = add_post_set_parameters_callback(', 'start_timer();')} />

<PlainWords>

Validate in the first callback, act in the second. The first must not change anything: if any parameter in the same request is refused, none of them is set, and you would have acted on a change that never happened. Keep the handles the two functions return, as the blinker does in `check_` and `apply_`: when a handle is destroyed, its callback is removed.

</PlainWords>

<Recap>

- A **parameter** belongs to one node: declared with a default (`declare_parameter`), optionally with a description and a range.
- Set at start by `--params-file` and `-p` (the last one wins), or a launch file's `parameters` list (in order); a value that fails the checks at start stops the node.
- `ros2 param list`, `get`, `set`, `describe` and `dump` from the terminal; a refused set leaves the value as it was.
- React to changes: refuse in an on-set callback, act in a post-set callback, and keep both handles.
- A YAML file is keyed by node name, with values under `ros__parameters`; `ros2 param dump` writes one.
- Next: putting topics, services, actions and parameters together into a robot's software.

</Recap>
